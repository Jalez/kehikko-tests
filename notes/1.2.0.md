- **How your project is tested, kept as named suites.** Each suite says what it proves and how to run it, and is kept in the project itself.
- **Run one and watch it.** Output, pass and fail counts and the verdict arrive as the run goes.
- **What was run for the change you are looking at.** Pick an issue, merge request or pull request and Tests shows what was run against it, when, and what happened.
- **Never "passed" by mistake.** Not run, passed, failed and "we do not know" are kept apart, so a run that was never made never looks like a pass; a reference outside the parts you picked says so.
